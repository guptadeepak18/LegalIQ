# LegalIQ

AI-powered Legal Health Score platform for Indian SMBs by Rest The Case — assesses businesses across 4 legal pillars and generates a scored report with AI-driven insights.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080, serves `/api`)
- `pnpm --filter @workspace/legaliq-web run dev` — run the frontend (Vite dev server)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string (auto-provisioned)

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5 (`artifacts/api-server`)
- Frontend: React + Vite + Wouter + Zustand + Framer Motion (`artifacts/legaliq-web`)
- DB: PostgreSQL + Drizzle ORM (`lib/db`)
- AI: Google Gemini via Replit AI Integrations (`@google/genai` SDK)
- Email: Resend (`RESEND_API_KEY` optional — OTP emails gracefully skip if not set)
- Auth: JWT (`JWT_SECRET`) for admin panel, OTP for public users
- PDF: jsPDF (client-side report generation)

## Where things live

- `artifacts/api-server/src/middleware/auth.ts` — JWT admin auth middleware

- `artifacts/legaliq-web/src/lib/api.ts` — Frontend API client
- `artifacts/legaliq-web/src/store/useStore.ts` — Zustand global state

## Architecture decisions

- Uses Replit AI Integrations for Gemini (no user API key required, billed to Replit credits)
- OTP emails via Resend — app gracefully degrades in dev if RESEND_API_KEY is not set (devOtp returned in response)
- Admin auth uses JWT (JWT_SECRET env var), seeded admin: admin@restthecase.com / Admin@123
- Assessment engine is fully adaptive — seed questions generated by Gemini, cached 6h per business type + city
- All API contracts defined in OpenAPI first, then codegen produces typed hooks + Zod schemas

## Product

- **Landing** (`/`) — hero section, how it works, testimonials, CTA
- **Onboard** (`/onboard`) — OTP-verified lead registration (name, company, phone, email, business type)
- **Assess** (`/assess`) — AI-adaptive questionnaire across 4 pillars (Litigation, Contracts, Compliance, Cost)
- **Results** (`/results`) — Scored report with AI insights, risk flags, action plan, PDF download

- **Review** (`/review`) — Post-assessment star rating and testimonial submission

## Gotchas

- OpenAPI body schema names MUST NOT match `<OperationIdPascal>Body` or `<OperationIdPascal>Response` — causes TS2308 in api-zod barrel. Use entity-shaped names (e.g. `LeadRegistration` not `CreateLeadBody`).
- Run `pnpm --filter @workspace/api-spec run codegen` after any OpenAPI spec change before typechecking.
- Admin seeding: `INSERT INTO admin_users` with bcrypt hash — seed script at `/scripts/src/seed-admin.ts`.
- Gemini uses `AI_INTEGRATIONS_GEMINI_BASE_URL` + `AI_INTEGRATIONS_GEMINI_API_KEY` (auto-provisioned via Replit integrations).
